# 微型局 01 · 拾光照相馆 · 首次实测记录

> 2026-10-04 夜。**这是 dsh-jubensha 的第一次真实验证**，目的不是「玩得爽」，是回答一个问题：**AI 玩家像不像人。**
> 参与：1 名真人（首次玩剧本杀）+ 3 个 AI 玩家（各自独立子 agent）+ 1 个 AI DM（主 agent）。

---

## 一、结果

- 真人玩家投票：**阿May** ✅ 正确（她是凶手，失手杀人）。
- 达成度：真人玩家**自己**找到了决定性破绽（见 §三）。
- 全场约 15 个来回，无卡死、无出戏。

---

## 二、验证目标与结论

**目标是三个可感知的问题**（因为玩家没玩过剧本杀，不能用「像不像真人局」当标准）：

| # | 问题 | 结果 |
|---|---|---|
| 1 | 有没有某个 AI 玩家的话真的影响了你的判断？ | **是**——阿May 的连续追问直接改变了桌面节奏，玩家被迫自证时间 |
| 2 | 有没有哪一刻你想追问某个人？ | **是**——玩家连续追问小满、老陈、阿May，并主动交叉验证 |
| 3 | 复盘时有没有「啊，原来是这样」的一下？ | **是**——「柜台上那沓钱」这一处是全场的破局点 |

**核心结论：成立。** 三个 AI 玩家的语气、句长、策略、攻防方式**互不混淆**，且都能生成 prompt 里没有写过的具体台词。

---

## 三、AI 玩家表现（按人）

### 阿May（压迫型 / 凶手）——最出彩

设计上她只有「谎报时间 + 主动进攻」两条策略，**没有写任何具体台词**。实际产出：

- 第一轮就咬真人玩家（"林默呢？他昨晚也来了吧"）——**主动开局**，没人要求她这么做。
- **自己造出三处破绽**，全部是模型为自保临时编造细节时自然露的（见下表），其中两处直接决定了游戏走向。
- 被围住之后**加大力度而不是退缩**，符合压迫型设定；结尾仍在死撑。

**关键发现**：她的破绽不是设计出来的，是**在压力下自然生成的**。也就是说，「凶手越用力自保、漏得越多」这个机制**不需要写进 prompt 也能出现**——但它需要 prompt 里明确写出「你会知道太多、你压得太猛」这类**破绽许可**，否则模型会演得太完美。

### 小满（记账型 / 无辜）

- **三次**把时间矛盾摆在桌上，且每次都克制（"这话我搁这儿，你们自己捋"）——完全符合「不拍桌子，只对时间线」。
- 最后一轮给出完整推理链，**主动把自己的软肋也摊出来**（"我站外头多久先放一边——你们要算就一块儿算"）。这句不在 prompt 里，是模型自己加的。
- **问题**：第一轮用了括号写内心活动（`（别的等会儿再说吧，先让他们讲。）`）——真人不会这么说话。第二轮起在 prompt 里明令禁止后消失。

### 老陈（藏拙型 / 无辜）

- 始终话最少，且**拒绝主动指控任何人**——即使最后投票轮，他也只是"跟证据走"。
- 第一轮那句「那天他话不多，我以为他累了」不在 prompt 里，是他自己加的——**这是全场最像真人的一句**（一个老人在回忆死去的朋友）。
- **问题**：出现了事实自相矛盾（见 §四）。

## 四、发现的三个技术问题（重要）

### 1. AI 玩家的跨轮记忆会漂移 —— 本次的硬伤

**现象**：老陈第一轮说「下了两盘。**我输了**」，第三轮说「**我赢了他**都没吭声」。真人玩家当场抓住这个矛盾，老陈只好解释成"一赢一输"。

**根因不在模型，在机制**：子 agent **每次调用都是独立上下文**，玩家记忆靠 DM（主 agent）把上一轮的台词手工重新写进 prompt。**这一次是我在重建背景时写错了**（写成"你赢了他一盘"，而他第一轮说的是"我输了"）。

**性质**：这是**DM 侧的数据损坏**，不是演员的失误。在真人局里不存在这个问题。

**推论（对插件设计是硬需求）**：玩家记忆**必须走结构化状态文件**（谁在什么时间说过什么、承诺过什么），由程序读写，**不能靠 DM 手工复述**。否则局越长、人越多，漂移概率越高，且**没有任何信号提示你漂了**——直到玩家抓包。

**附注**：这次漂移在游戏里**意外产生了效果**（它让无辜的老陈显得更可疑，正好撞上本子的"误伤"设计）。但不能依赖这种运气：误伤应该是**设计出来的**，不是 bug 碰巧撞对。

### 2. AI 玩家会编造出与设定冲突的事实

阿May 说小满「**你上个月才来的店里**」——而设定里小满跟了老周**两年**。她不知道这个信息，为了贬低对方可信度而编了一个。

**性质**：这是"知道太多"的反面——**知道的太少但敢说**。真人玩家也会干这事，但真人有底（他知道自己不知道）；模型没有这个边界感。

**处置方向**：给每个 AI 玩家的 prompt 里加一条**「你可以编，但不能编与公开事实冲突的东西」**，并把「公开事实」做成一份共享的只读清单。

### 3. 格式瑕疵：括号内心戏

小满第一轮用了 `（别的等会儿再说吧，先让他们讲。）`。这是"跑团括号"的习惯，不是剧本杀的说话方式。**在 prompt 里明令禁止后即消失**——属于容易修的一类。

## 五、机制层面的意外收获

1. **「行为泄漏」真的会自动发生。** 我给了阿May 一条"破绽许可"（你会知道太多、你压得太猛），她就真的在压力下漏了 —— 而且是**用我没想到的方式**（"柜台上还摊着钱"）。这说明设计文档 §2.4 那条判据（性格与秘密的错位是内容，不是漏洞）**在实现上成立**。

2. **信息隔离是真的隔离。** 三个 AI 玩家各自只拿到自己那份角色本，**全程没有互相泄漏**；真人玩家从头到尾没见过任何 AI 的私密信息。

3. **「读人」层确实生效。** 真人玩家在最后阶段的主要动作不是读物证，是**读三个人的反应方式**（谁绕开了问题、谁在重复、谁开始用力）。三个盲区不同的设计，让"该信谁"变成了一个真实的问题。

4. **DM 不给暗示也能带新手。** 全程只做过两次流程提示（"该搜证了"、"账本上那个字全桌有人知道"），玩家自己完成了其余推理。

## 七、真人玩家反馈（同日回访）

### 7.1 三条反馈与设计结论

**①「张姐出摊的事，我的卡片上没有这个信息，我只能找小满佐证。」**

真缺口。玩家（林默）是常客、是侄子，理应熟悉这条街，但角色卡**没给任何"环境事实"**，于是他没法自己判断阿May 那个来源的真假，只能等 NPC 发话。

**处置**：角色卡要附一份「你知道的环境常识」（这条街有什么店、谁跟谁熟、老周的习惯）。**玩家自己抓破绽的能力，取决于他手里有多少可自证的锚点。**

**②「我倒是想问问拆照相馆的事，我以为是个什么暗线呢，其实并不是。就是普通拆迁，并且角色卡也没和我说拆迁的事，我有点懵。」**

真缺陷。「店要拆了」在开场、老陈、老周三处被提到，**写得极显眼，却没有任何作用**——玩家当然会去挖。

**教训：你写得越显眼的细节，玩家越会当线索。要么让它有事，要么别写那么重。**

**③「我担心的反而是账单那里，我担心是凶手的障眼法，照片反而被我排除了。如果照片真的是线索，那为啥凶手只抢了一半，从一个死人手里拿走另一半很简单啊，为啥要给自己留把柄呢？所以我判断这个底片实际上不影响剧情。」**

**这条最有价值，而且他的推理是对的。**

理性玩家会对每条物证做同一个检验：「它能不能定罪？」那半张底片通不过——凶手没理由给自己留把柄。于是他**合理地**排除了它。

而它确实是**情感线索，不是破案线索**（老周正在洗的就是那张照片，他攥住它是因为没来得及松手）。

**结论：情感线索不能伪装成破案线索。** 理性的玩家会去检验它"作不作为证据"；检验不过就丢掉——**而且排除得越有道理，情感丢得越干净**。

**处置**：情感线索走**搜证之外的渠道**（桌上没写完的信、抽屉里一张没装框的相纸），在形式上就明显"不参与推理"；或者接受理性玩家会错过它，**别把情感当成设计的支点**。

### 7.2 一条元观察

「咯噔一下」这个验收指标在**首次测试局里可能不适用**：玩家全程处在「测机制」的心态中，谈不上情感投入。情感投入要靠第二局以后——这也正是「AI 玩家需要跨局记忆」的另一半理由。

## 八、机制实测：AI 玩家能不能持续？

**问题（由用户提出）**：能不能让一个子 agent 一直玩，而不是每轮新建？

**实测结论：`subagent` 在本会话里是一次性的。**

- 后台创建一个探针 agent 后，`list_agents` 里**查不到它**（只列 durable teammate）；
- `send_message` 到它的 id 报 `active teammate "<id>" not found`。

所以「每轮新建 + DM 手抄重建」**在当前工具下不是一种选择，而是唯一路径**——§四.1 那个记忆漂移因此是**机制性的**，不只是操作不慎。（此前我把原因全归给"我写错了背景"，那说法不完整：写错是真的，但根子在这条路径**只能手抄**。）

**另一条路：`spawn_teammate`（2026-10-04 当晚实测通过）**

创建了三个持久队友（`lao-chen` / `a-may` / `xiao-man`）。四项实测：

| 检验 | `subagent` | `teammate` |
|---|---|---|
| 创建后是否出现在 `list_agents` | 否 | **是** |
| `send_message` 送达 | 报 `active teammate … not found` | **`accepted`** |
| inactive 后能否被唤醒 | —— | **能**（发完消息它回话） |
| **上下文是否保留** | 每次全新 | **保留** |

**上下文测试方法（关键在于只能靠上下文回答）**：先 `send_message` 让它「把上桌的第一句话照着再说一遍」（它准确复述，但这还不能判定——可能是重新生成的同一句）；再问「我上一条消息让你做什么」，它答**「让我把上桌的第一句话照着再说一遍」**。这个信息不可能从人设推出来，**只能来自上下文**。

**结论：§四.1 那个记忆漂移有解了。** 三个玩家 agent 从此记得自己说过什么、桌上发生过什么，DM 不需要手抄重建。**这是本项目的架构定案：AI 玩家用 `spawn_teammate`，不用 `subagent`。**

**两条实测到的坑**：

1. **teammate 的输出以 `Background subagent <uuid> finished` 的形式回到 Lead**（不是"某成员发来消息"），而 `wait_agent` 对它报 `no-active-peer`——它 inactive 时等不到，`send_message` 却能唤醒。**判据：不要用 `wait_agent` 等它，直接发消息然后等通知。**
2. **teammate 工具权限完整，会自己找路**：探针 agent 曾无视「不要使用任何工具」的指令去调 `memory_save`（并在记忆库里留下一条垃圾记录，已删）。用于角色扮演时必须**显式划边界**——只准说话、不准读写文件、不准互相私聊。

**待办**：下一局用三个 teammate 当玩家跑一次。代价与风险：teammate 是为工程协作设计的（会自己动工具、写文件），用在游戏里没有先例，需要给它明确的边界（不许写文件、不许调用工具、只准说话）。

## 九、遗留

- 本子本身的表现很好（三条线索 + 三个"其实不是" + 误伤设计全部生效），**不需要改**。
- 真人玩家是首次玩剧本杀，却自己找到了决胜破绽（"柜台上还摊着钱"）——**这个本子对新手是够友好的**，可以作为以后新本的难度基准。
