# 房间与设置 —— 界面设计

> 2026-10-05。**权威的样子在 [`原型/房间-原型.html`](原型/房间-原型.html) 与
> [`原型/设置-原型.html`](原型/设置-原型.html)**——那两份是能点的，改版式先改它们。
> 这份文档写的是它**为什么长这样**，以及**每一块的数据从哪来**；机制（一个包两个半边、
> 只读端点、槽的选型、围栏）在 [`2026-10-05-房间面板.md`](2026-10-05-房间面板.md)。

## 0. 两条总则

**① 界面是附加层。** 宿主侧的工具、局面状态机、演员池不为它改结构。所以下面的每一个区块
都要能回答「数据从端点哪个字段来」——答不上来的，就是该补进端点或补进宿主侧的东西。

**② 两种形态各自完整。**

| | 走哪 | 什么时候 |
|---|---|---|
| 对话页 | 直接在对话里玩 | 摸鱼——隐蔽，但体验差（要在聊天里翻线索、记时间线） |
| 团队页 | 标签里的工作台 | 正玩——三栏摊开，线索、关系、时间线都在眼前 |

**这条决定了房间页必须有消息流**：如果它没有，正玩的人还得切回对话页看别人说了什么，
那就成了"两处都不完整"。同理，**房间页不重造输入框**——DSH 那个输入框就在标签下面，
它就是对话页的那一个，两种形态共用同一局。

## 1. 层级

```
会话视图（DSH）
├─ 标签栏：对话 / 轨迹 / 团队 / 上下文        ← DSH 的，不是插件的
│   └─ 「团队」标签的容器                      ← 便签挂在这里（position: relative）
│        ├─ 三栏
│        └─ 便签层（position: absolute）
└─ 输入框（DSH 的，在标签下面）                ← 说话用它，不另造
```

**便签归标签页管，不归窗口管。** 它挂标签容器、坐标相对容器，所以切到别的标签时它跟着
这一页一起消失，切回来位置分毫不动。**但它的状态（位置 / 颜色 / 文字 / 序号）存在宿主侧、
按会话分**——不然切走再回来就丢了。

设置页在另一个地方：**设置 → 插件 → 剧本杀**（挂 `settings.plugins.tab`，不是
`settings.section`——功能插件不占左边那列导航）。

## 2. 房间页

### 2.1 顶部：阶段条

五个阶段横排，走到哪亮到哪：自述 → 问话 → 搜证 → 发言投票 → 复盘。

**它同时是切换器**——点哪个阶段，中栏就换成那个阶段的页面。进度与导航是同一件东西，
不必再做一个下拉。

### 2.2 左栏：这一局的人

| 区块 | 显示什么 | 数据来源 |
|---|---|---|
| 这一桌 | 每个座位的头像、角色名、身份、演员；没上桌的位子显示「还没上桌」 | `game.seats` + `players` + `cases[].roles` |
| 人物关系 | 连线图：死者居中，四条关系各自带标签（叔侄 / 棋友三十年 / …） | **缺**：`roles[].public` 有的是身份短句，关系的**形状与标签**现在没有字段 |
| 时间线 | 只显示**每个角色自己说过的**时段，没交代的留空 | **缺**：要从对话里收集，见 §5 |

**时间线不显示真相。** 真相在 DM 手里、复盘前是封着的——能出现在这儿的只有玩家听过的话。
这不是设计上的克制，是封存机制的直接后果（`sealed()` 按会话判，与上下文无关）。

### 2.3 中栏：主区（限宽 640 居中）

**顶部常驻剧本正文**，默认展开、可折叠——回看用的。下面跟着当前阶段的页面。

限宽不是审美：**正文的行宽有最佳值**，铺满一屏反而难读。两侧因此可以放得更宽。

五个阶段页各显示什么：

| 阶段 | 页面内容 | 数据来源 |
|---|---|---|
| 自述 | 逐个上桌：每个 AI 玩家说了什么、谁还没上桌 | 对话 + `players` |
| 问话 | 每个人「说过的」清单——他说了什么、**没**说什么 | **缺**：要从对话里按座位归集 |
| 搜证 | 线索卡：已发的展开，未发的显示成背面 | `game.revealedClues` + `cases[].` 本子的 `clues`；**发放状态就是 `revealedClues`** |
| 发言投票 | 每人说了一轮「怀疑谁、为什么」；轮到你时提示直接说 | 对话 |
| 复盘 | 真相、那一夜五段、三个「其实不是」 | `truth`（此时已解封） |

**线索卡是「还剩几条」的读数**：未发的显示成背面，一眼看得出还差几条。

**「引用到对话」按钮是做的**，但**它得有自己的位置**——卡片里那个按钮，不是右键菜单。
右键那套是「添加到会话」那类插件的入口，撞上去才是冲突。

### 2.4 右栏：桌上说了什么

**只读的消息流**，加上一句「说话在下面那个输入框里」。它是团队页自足的那一半：
正玩的人不必切回对话页才知道别人说了什么。

## 3. 设置页

**只放跨局的东西**。判断是：**换一局它还成立吗**——演员是，座位不是。

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 演员 | 名字、性格、头像、**跨局印象（只读）** | `actors`（读）+ **写端点** |
| 本子来源 | 插件自带（只读，显示有几本）+ 自定义目录（可加可移） | **缺**：现在只扫插件自带的 `cases/` |

**跨局印象是只读的**：那是每局复盘后自己攒起来的，让人手改等于伪造他的记忆。

**性格在这里手写**，LLM 起草仍留在对话里（`jubensha_actor action="draft"`）——设置页是
浏览器半边，它调不了模型。

## 4. 便签

右键页面任意位置留一张；九色（**白底排第一格，最隐蔽**）；**自增序号** `#1 #2 …`；
点开就能改；`✕` 删掉。序号是给「引用」用的——游戏里说「便签 3 那条」比复述一遍省事；
删掉的号不回收。

**便签不进对话、不进模型上下文**：它是给自己看的备忘，不是发言。

**存放处不该是浏览器。** 便签要跟着人走（换台机器还在），而状态按会话分——落点该是宿主侧
存储，与演员池同一层。原型里落 `localStorage` 只是为了能验交互。

**它比剧本杀更通用**：右键在任意界面留便签，对所有 DSH 界面都有用。所以它将来该**独立成
插件**，剧本杀只是第一个用户；在抽出去之前，先做在房间页里。

## 5. 实现要动的

按依赖排，前两项咬得最紧、建议一起做：

1. **端点的写路径**：演员池（设置页要写）、便签（位置/颜色/文字/序号，按会话存）。
   仍是同一套 loopback + 同源围栏，服务端只认自己那几个字段。
2. **客户端重做**：三栏 + 五阶段 + 便签层。标签的 `inject` 给 `sessionId`，快照按它取。
3. **设置页**：挂 `settings.plugins.tab`，`label` 用「剧本杀」，`order` 排在「全部插件」之后。
4. **补数据**（端点侧，按需要）：线索发放状态（已有 `revealedClues`，把它按条给出来）、
   关系图的形状与标签、按座位归集的「他说的时段」、本子来源目录。

## 6. 故意不做的

| 没做 | 为什么 |
|---|---|
| 房间页再放一个输入框 | DSH 那个就在标签下面，而且就是对话页那一个。另造一个会跟「添加到会话」那类插件抢同一个位置 |
| 投票下拉框 | 投票本来是**要说出口**的东西——说了别人才接得上话 |
| 真相时间线（做在玩家的时间线里） | 它是封着的。封存按会话判、与上下文无关，这不是取舍 |

**判断是一条**：**凡是 DSH 已有的东西，不在这里再造一遍**；而**它没有、又不与别人抢位置的**，
该做就做。

## 7. 还没验到的

实现已经落地（房间三栏、五个阶段、便签层、设置页），下面这两处**在真界面里还没看到过**：

- **设置页有没有真的出现在「设置 → 插件 → 剧本杀」**。**结论：思灵这个壳里看不到，而原因不在插件——壳里没有 DSH 的设置面板。**

  查证的链路：官方 checkout 有 11 个 `ui-settings-*` 包（`ui-settings` / `ui-settings-general` /
  `ui-settings-plugins` / …），而**隔离实例的两个 profile（`ssid` / `ssid-dev`）与真实 profile
  里一个都没有**；壳那一侧也没接管（整个 `ssid-desktop` 里只有一处 spec 的类型导入提到它）。
  所以 `settings.plugins.tab` 这个槽**根本没人声明**——而 `ctx.slots.inject` 会安静地等一个
  不来的声明，于是在页面上既看不到入口，console 也干净。

  页面上那些 `aria-label="设置"` 与 `aria-haspopup="dialog"` 都排查过了：前者只有思灵侧栏菜单
  里的一项，后者四个分别是「智能体团队」与三个状态栏读数——**都不是 DSH 的设置入口**。

  插件这边没问题：它照官方约定挂的，在装了那套面板的地方（官方 web 版）会出现。
  **要不要在思灵里也有设置页，是个需要拍板的事**——另挂一处（比如侧栏那个菜单里），或者
  壳把 DSH 的设置面板装上。
- **便签的「真右键弹色板」**。上一轮验留便签时那一下被插件更新浮层接走了（试了 12 个点全在
  `pc-overlay` 上），而手动派发能弹出色板——所以监听那条路是通的，缺的是"浮层不在时真人点
  一下"这一次。

两处的共同点值得记：**它们都不是功能没写，是"验证被别的东西挡住了"**。而挡住的两种样子——
找不到入口、被浮层盖住——都会伪装成"功能坏了"。
