# 单机剧本杀 · 设计方案（v0.1 · 设想阶段）

> 起意：2026-10-04。插件名 **`dsh-jubensha`**（2026-10-05 定，见 §5）。
> 状态：**已过三局实测**（01 推理 / 02 推理 / 03 情感），正在搭插件骨架。
> 本文档自包含地记录从「AI 能不能当 DM」一路推到「插件长什么样」的完整推演与判据，不依赖产生它的那次对话。

## 0. 一句话

主 Agent 当 DM，子 Agent 当玩家，你也是玩家——**凑不齐人，也能开一局**。

---

## 1. 问题与定位

### 1.1 真实门槛不是钱，是人

剧本杀的开局门槛是：需要一个 DM（他全知、又不参与），需要 4–6 个同时有空、且愿意玩同一个本的人。**凑不齐就开不了局。** 线上 App 解决的是「陌生人拼车」，但拼车本身有社交成本，而且 DM 依然是个人。

本插件的定位：把「人」这一侧补齐——**DM 与其余玩家都由 agent 承担，人类玩家只需一个人。**

### 1.2 为什么 AI 当 DM 是结构性匹配，而不是将就

剧本杀 DM 的处境可以点名为五处空缺（表格来源：2026-10-04 的设计推演）：

| 参与感的来源 | 玩家 | DM |
|---|---|---|
| 信息差 | 手里有别人不知道的秘密 | 全知，信息差为零 |
| 不确定性 | 不知道凶手是谁 | 知道结局，连过程都预演过 |
| 选择权 | 发言和选择能改变局势 | 能控场，但不能选结果——一选就是作弊 |
| 身份代入 | 有动机、有关系 | 无角色，NPC 台词是写死的 |
| 胜负后果 | 有目标，要承担结果 | 裁判，无目标也无后果 |

DM 唯一剩下的是第六行——**看别人第一次被反转击中**。但那是**二阶体验**：玩家的满足感由自己直接产生，DM 的满足感要从玩家的反应里派生。**依赖外部喂养的东西必然衰减**：同一个本带到第十次，看第十一个人被同一个反转击中时已经什么都不剩。这是结构性的，不是心态问题。

**关键推论**：这个位置的缺陷是「没有参与感」，而 agent 恰好不需要参与感。**缺陷与替代者的属性正好互补**——所以 AI 做 DM 不是降级方案，是错配被解开了。

> 旁证：**演绎本对 DM 更友好**，因为它把 DM 从裁判变成了演员，参与感立刻回来一半。这从反面说明「参与感的缺失来自位置，不来自能力」。

### 1.3 玩家这边不会被坑吗

一旦 DM 有立场（比如 AI 想赢），全知 + 控场权 + 玩家不知情 = 不公平。但「不公平」要拆开看——它由四件事构成，其中只有两件是真问题：

| 造成不公的要素 | 要不要拆 | 怎么拆 |
|---|---|---|
| 有立场（DM 想赢） | 不必拆 | 公开就行——跑团 GM 和桌游里的城主都站在对面，没人喊不公 |
| 立场藏起来（玩家不知道在跟谁打） | 必须拆 | 开局讲明：这一局 DM 是对手，不是服务员 |
| 全知（他手里有你的暗牌） | 可以削 | 关键选择同时提交、封存，DM 也要开牌才知道 |
| 权力没约束（给不给线索全凭他说） | **这是真问题** | 把他的权力从「裁决权」换成「资源权」——有牌组、有点数、行动集合公开 |

**判据**：权力叫「裁决」就必须中立，权力叫「资源」就可以有立场。裁判吹哨子决定别人命运，所以他必须中立；城主自己也在走棋，只是他走的棋有明码标价的资源。

**更深的伤害**：不公真正毁掉的不是输赢，是**玩家的能动性**——你怀疑的每一条线索都可能是被安排给你的，那你不再是在探案，是在猜作者的意图。

**本项目的落点**：v1 的 DM 保持**中立服务位**（顺理成章地回避了这个问题）；「有立场的 DM」作为一种本子范式留到以后（§5 待定）。

## 2. 核心设计

### 2.1 信息隔离：三条信道

```
你(玩家) ←──发言/公布──→ 我(DM)
                            │ 写入
                            ▼
                       [剧本文件]
                        │   │   │
              只喂自己那份│   │   │
                 ┌──────┘   │   └──────┐
                 ▼          ▼          ▼
            AI 玩家 1   AI 玩家 2   AI 玩家 3
                 │          │          │
                 └────发言──┴────发言──┘──→ DM
```

**规则只有一条**：**会话对话 = 桌面，只能出现公开信息；AI 玩家的剧本永远从文件直接进子 agent，不经过对话。**

| 信道 | 谁看得见 | 装什么 |
|---|---|---|
| 会话对话 | 玩家 + DM | 公开桌面 + 发给该玩家的私密信息 |
| 剧本文件（`players/pN.md`） | 各自一份 | 每个角色的秘密与任务 |
| 子 agent 上下文 | 只有那个 AI 玩家 | 它的剧本 + 它经历过的全场发言 |

这么做的好处是：**人类玩家拿到的东西天然是干净的**——AI 玩家的私有信息从不进入他会看到的信道。

### 2.2 人设分两层

- **第一层：角色人设**（剧本内的身世、性格、动机、说话方式）——这是**及格线，不是加分项**。没有它，AI 玩家发言就是信息交换机器人，一眼假。
- **第二层：玩家性格**（这个人怎么玩游戏）——**真正有意思的地方在这里**。它跟角色无关，且**跨局稳定**。

同一份剧本换个人玩，玩法完全不同：

| | 藏拙型 | 压迫型 | 记账型 |
|---|---|---|---|
| 说话 | 短、只答不问，基本不抢话 | 连珠追问，用问题逼人自相矛盾 | 不吵架，只反复对齐时间线和在不在场 |
| 决策 | 等别人先暴露，自己最后表态 | 抓到一点就往前压，宁可压错 | 攒到有把握才开口，一开口就定人 |
| 破绽 | 安静本身就被怀疑「他怎么不聊」 | 太猛，像在转移话题 | 憋太久，突然精准反而可疑 |
| 在局里天然的位置 | 最容易当第一嫌疑人 | 最容易被烦但不容易被票 | 往往是最后定罪的那个 |

第二层值钱的地方：**它给游戏加了一层「读人」的信息**。如果三个 AI 都一个腔调，玩家只是在读线索；风格拉开了，同一个行为在不同人身上意味着不同的事——安静的人是心虚还是在攒牌，得分人判断。

### 2.3 判据：人设要写成「他会怎么选」

**形容词列表（「性格火爆、心直口快」）一出手就被识破是表面功夫，也影响不到任何决策。写成决策偏好，性格才会在票型上留下痕迹。**

进阶版（由 2026-10-04 的第二轮推演得出）：**写到「他想选什么，但实际做成了什么」**——即人设要写出**欲望与能力的缺口**。

### 2.4 反差感：性格与秘密的错位是内容，不是漏洞

**这是本项目最有价值的一条设计判断。**

最初的判断是「性格必须和秘密相容，否则会漏嘴、破坏游戏」。这个判断**只对功能位（凶手本人）成立**。对人设来说，**那个缺口才是戏**。

原型来自《甲方乙方》里那个想体验「打死我也不说」的胖厨子——**平时嘴上没把门的人，愿望偏偏是守口如瓶一次**。他的愿望不是「守住一个秘密」，是「体验自己能守」：**他要的东西正好是他做不到的**。这个角色在局里不是「在藏秘密」，是「在跟自己的嘴打架」，而全场都在看这场架。

**他漏出去的是行为，不是内容**——这才是反差感的来源：

| 拍子 | 发生了什么 |
|---|---|
| 嘴边 | 秘密就在嘴上，他随时能说出口 |
| 堵回去 | 用「我没什么好说的」把它压住——但这句话本身就是个信号 |
| 说别的 | 憋不住，于是补了一堆没人问的细节：几点睡的、看了什么电视、谁打的电话 |
| 越补越可疑 | 别人问一句他答三句。最后他招的不是秘密，是「**我有秘密**」 |

两条判据：

- **防御姿态本身就是公告。** 他说出来的那些细节可能无害，但所有人都从他使劲的方向上看出了东西。
- **行为泄漏 ≠ 内容泄漏。** 行为泄漏制造的是**需要解读**的信息（推理增值）；内容泄漏是免费信息（游戏贬值）。设计上永远优先制造前者。

**DM 侧的处置（三条）**：

1. 让他漏出去的那部分**指向疑点，别指向定论**——他暴露「我有事」，但不直接砸穿谜题；
2. 一局里这种角色**最多一两个**，人人都在憋着不说就没谜了；
3. 最好玩的形态是——**他其实是无辜的**，他的秘密是别的事（那天他确实撒了谎，但跟案子无关）。全场因为他的守不住而围着他转，最后发现冤枉了他。**误伤是剧本杀的高光时刻**，而制造这种误伤最省力的办法，就是放一个这样的角色进去。

## 3. 技术方案与风险（待验证）

### 3.1 组件映射

| 需要的机制 | 现有件 | 状态 |
|---|---|---|
| AI 玩家（各自独立上下文） | 子 agent（`subagent`）——每次调用独立上下文，正好满足「一人一份秘密」 | 已验证的工具能力 |
| 玩家记忆（跨轮） | 文件（`players/pN.md` + 全场公开记录），每轮重建 prompt | 待验证 |
| DM 全知 | 主 agent 上下文 | ✓ |
| 桌面可见性 | 会话对话 | ✓ |
| 跨局人格连续性 | `dsh-memory`（persona 树干 / 记忆分叉） | 待设计 |

### 3.2 两个已知风险

**风险一：剧透通道（约定问题，不是技术问题）**

DM 全知，秘密都在主 agent 的上下文里，而玩家的界面能看到思考块与工具操作条——**展开就能看见**。纪律是「AI 玩家的秘密只走文件、不进对话」，但这半边靠的是**玩家自觉不展开操作条**。

可接受性：剧本杀本来就是要复盘的，唯一会被毁掉的是「玩之前被剧透」，且毁掉的是玩家自己的体验。**但它必须在开局前讲明。**

**风险二：AI 玩家会不会一眼假（真正的生死线）**

- 优势：**隐藏信息是物理隔离的，不是表演的**——AI 玩家被骗是真的被骗，那份慌张不是装的。
- 劣势：**跟朋友玩时你的怀疑有一半来自「我认识他」**（他刚才那个停顿不对劲）。AI 没有这层质地，人际张力会薄掉。

**所以第一局的重点不是本子精不精彩，是「发言像不像人」。** 验收标准：**玩家会不会忘记对面有几个是 AI。**

### 3.3 待验证清单

- [ ] 子 agent 在只拿到自己那一份信息时，会不会**从别处泄漏**（例如从公开信息里反推出不该知道的事并说出口）
- [ ] 每轮重建 prompt 的**上下文成本**：一局 N 人 × M 轮，每次调用都要带完整剧本 + 历史 → 成本是 N×M 的乘数
- [ ] 人手一 agent 与「一个 agent 扮演多个玩家」的取舍（后者会破坏信息隔离，见 §2.1）
- [ ] 「守不住」四拍动作序列写进 prompt 后，模型能不能**真的演出挣扎**而不是直接说漏

### 3.4 插件要提供的工具（从两次实测里长出来的）

按出现顺序，这是跑下来**真实缺的**东西——不是设想：

| # | 要解决的问题 | 实测依据 | 工具形态 |
|---|---|---|---|
| 1 | **本子只有我能写** | 两本都是手写 Markdown，谁想玩都得找我写一本 | 本子 schema + 加载器（**已实现**：schema v1.0 + `jubensha_case`，见下） |
| 2 | **玩家 agent 控不住** | 记忆探针无视「不要使用任何工具」，仍调 `memory_save` 并污染记忆库（已删） | `jubensha_player`：创建**只有说话能力**的 agent（已实现，见下） |
| 3 | **跨局记忆** | teammate 是会话内成员，一局结束就散；「我记得上局被谁骗过」做不了 | 玩家档案 + 印象条目，落盘、下局读回 |
| 4 | **信息路由靠我自觉** | 第一局的记忆漂移就来自手抄重建 | 桌面频道 / 私聊频道，程序保证不串（**桌面已做**：`say seat="*"` 广播 + `relay` 转原话，见下。**私聊未做**） |
| 5 | **状态靠我脑子记** | 第几阶段、谁搜了什么、线索给没给 | 状态机 + 事件日志，复盘 = 读日志（**已实现**：`jubensha_state`） |
| 6 | **真相在我上下文里** | 我的思考对玩家可见 | 真相保险箱：只返回「该给什么」，不返回「为什么」（**已实现**，见下） |

**第 1 条（本子格式与加载器）—— 2026-10-05 已实现并实测通过**：

`schema/case.schema.yml` 定稿到 v1.0，`src/case.ts` 是加载器，`jubensha_case` 是它在工具面上的出口。
完整记录见 [`2026-10-05-本子格式与加载器.md`](2026-10-05-本子格式与加载器.md)。三句话：

- **定稿靠拿一份真实本子逐字段填**（把 case-03 转成 YAML），填不下去的地方就是缺口——一次填出五处：
  `roles[*].now`、`roles[*].play`、`scene.premise`、`truth.after`，以及
  `briefing` / `style` / `audit` / `reveal` 四整段。**格式的缺口不是想出来的，是填出来的。**
- **只把 `roles` 结构化**，别的段落原样留着按段取——角色本要按座位切，切口必须精确；
  真相与带局脚本是给 DM 读的整块文本，拆开反而丢信息。
- **角色本不再手抄**：`jubensha_case action="book"` 的输出直接就是 `jubensha_player` 的 `roleBook` 参数。
  实测那一串一字不差地传了过去。

**第 2 条（`spawn_player`）—— 2026-10-05 已实现并实测通过**：

完整机制、源码位置与实测记录见
[`2026-10-05-spawn_player-可行方案.md`](2026-10-05-spawn_player-可行方案.md)。三句话：

- **玩家仍走 Team**（`spawnTeammate`），前两局的实践与 roster 都留着。它的持久性来自
  `ctx.subagents.startContinuable`（`agent-team/src/roster.ts:282`）。而 `SpawnTeammateRequest`
  六个字段里**确实没有工具集字段**——所以收窄不由创建接口给，**改由插件自己在玩家的 agent ctx 上挂**。
- **收窄是两层**：`tools.restrict({ allow })` 管看不看得见（把继承层的 146 个工具清到 0）；
  `tools/pre-execute` 管准不准执行——它按**执行者本人的 scope** 路由，所以连 agent 自己那层
  （内核委派工具 `subagent` 就注册在那里）也拦得住。第二层是官方指的路：
  `shell/tool-bash/src/index.ts:9` 的 TODO 原文 `deployment policy belongs in tools/pre-execute`。
- **实测**：玩家跨 5 次请求只有一种工具面（10 个）；`list_agents` 与「对非主持人说话」都被闸拒。
  两次时序坑（挂得太晚、只挂给一个会被重建的对象）记在方案文档 §六。

**另一条被堵死的路**：会话的 file policy 若为 `danger-full-access` 且审批禁用（需审批的动作自动拒绝），
「让 teammate 的文件操作弹审批」就走不通——除非改会话策略，而那会同时限制 DM。

**第 6 条（真相保险箱）—— 2026-10-05 已实现并实测通过**：

完整记录（含一次失败与它逼出来的修法）见
[`2026-10-05-真相保险箱.md`](2026-10-05-真相保险箱.md)。三句话：

- **判据是白名单 + 默认封存**：只有八段随时可取，其余封到复盘。理由是**漏的代价不对称**——
  漏掉该开的，DM 当场就知道；漏掉该锁的，是玩家的操作条里静静躺着一份真相，**谁也不会发现**。
- **角色本过手不过目**：`book` 在封存期只给一串引用，全文留在插件里，`spawn` 时由程序自己解开
  送进玩家的首条消息。DM 从头到尾没读到过——**这顺带堵死了"DM 转述时抄漏一句"**。
- **实测里失败过一次**：DM 把整段返回值填进 `roleBook`（而不是里头那一串引用），于是"只认整串相等"
  的解析判它作废，玩家只拿到两行摘要——而 `spawn` 成功、玩家照常说话，**从外面完全看不出来**。
  修法是解析认"文本里含有引用"这一档，并把渲染文案改成引用独立成行。

**第 4 条（信息路由）的桌面一侧 —— 2026-10-05 已实现并实测**：

完整记录见 [`2026-10-05-桌面与信道.md`](2026-10-05-桌面与信道.md)。三句话：

- **先把「玩家根本说不了话」修掉**：brief 曾告诉玩家发给主持人的 `agent_id`，而 Team 的
  `send_message` 按成员**名字**解析（`agent-team/src/mailbox.ts:120`），那个 id 不是名字——
  于是某位玩家十次全失败，**从桌面上看只是「她很安静」**。修法：只给 `lead`，闸也只放 `lead`。
  **放行一个走不通的名字，比拒绝它更坏。**
- **桌面**：`say seat="*"` 一次说给全桌（逐个手发正是"漏掉某个人"的来源，而漏掉的那位不会知道）；
  `relay` 把某位玩家刚说的话转给其余人，用的是 `tools/result` 钩子当场记下的**原话**，不是复述。
- **私聊一侧没做**：人类玩家没有私聊信道，会话对话就是桌面。而 relay 仍要主持人调一次——
  这是有意的（把"谁听见什么"留给主持人），不是自动广播。

**新发现的拦路石（未解决）**：Team 名册上限 8 且**成员不可移除**
（`agent-team-profile/cordis.patch.yml:20` 的 `maxMembers: 8`；`roster.ts:65` 写明 immutable），
而 `unseat` 只清插件自己的座位表。所以**一个 DM 会话开不了三局**（每局 3 位 AI 玩家）。
出路：换会话，或把那个 `maxMembers` 配大。

完整的调研结论、证据与方法学说明见 [`docs/调研/2026-10-04-同类竞品调研.md`](../调研/2026-10-04-同类竞品调研.md)。

三句话摘要：

1. **DSH 插件生态内空白成立**——两个独立权威源（Oh-My-DSH 2125 条 / awesome 1.3 MB 清单）检索社交推理关键词均**零命中**，「皮肤与娱乐」162 条逐条通读亦无同类。
2. **生态外形态已被验证**——[wolfcha](https://github.com/oil-oil/wolfcha)（一个真人 + AI 填满桌子）与 [ai-murder-mystery](https://github.com/ScottishFold007/ai-murder-mystery)（多智能体剧本杀）各自做到了我们设想的一半。
3. **可守的差异点**：①「本子 vs 规则」（剧本杀有内容资产，狼人杀只有规则）；②DM 这个位子及其全部设计空间；③**跨局**（而非每局内）的人格连续性。

| 4 | **产品形态：两种并存** | **2026-10-05 用户提**：① **对话形态**（默认，只注册工具、不发界面元素）——用户原话「**极其隐蔽，适合摸鱼**」，在聊天窗口里它看起来就是普通对话；② **房间面板/弹窗**（后续）——布置 AI 玩家与 DM、看局面与阶段的真正游戏界面。**两条都要，不是前者被后者取代**：磨掉对话形态等于砍掉它唯一的、面板给不了的用处。**架构含义**：界面是**附加层**，宿主侧的工具与状态机不得依赖客户端存在。 |
